form-contract

One function turns a validator into a form.

A resolver is a plain function from your schema to a description of the form it implies. No registry, no vendor tags, no code generation — the same shape react-hook-form already asks of you, carrying the value type so that every path stays type-checked. 

type FormResolver<TSchema, T, TPath extends string = string> =
  (schema: TSchema) => FormAdapter<T, TPath>;

interface FormAdapter<T, TPath extends string = string> {
  readonly fields: readonly FormFieldDescriptor[];
  validate(root: unknown): MaybeAsync<readonly FormIssue[]>;
}

That is the whole contract. A validator able to describe its own fields implements it directly; one that cannot gets a resolver written for it once.

Three layers, and the third is plain React

Schema-driven form libraries usually buy their convenience by taking the markup away. Here the generated screen is the top layer rather than the only one, and dropping to the bottom layer costs nothing.

1 — AutoForm

The descriptors draw the screen. Nothing to write.

2 — Name a widget

Keep the layout, choose what a field renders as.

3 — Your own JSX

A hook per field. The library stops having an opinion.

A field subscribes by mounting and by nothing else, so splitting a form across components, a portal, a lazy boundary or a wizard step stops being a case the library has to handle.

Measured, with the losses printed first

Five runtimes are driven through one scripted transcript against one zod schema the harness owns and instruments, rendering one DOM the harness owns and hashes. Every count comes from the fiber tree, a MutationObserver, or a schema wrapper the harness placed — never from code an adapter author wrote.

form-contract is not first on this table, and the report says so before it says anything else. The scoped react-hook-form configuration commits nothing for a keystroke that does not move a verdict — and the same row records that it still ran a full schema pass to find that out.

The timing lane refuses to call its own author a winner

In headless Chrome at 201 fields a keystroke through form-contract measures 0.63x the hand-written reference. The report prints indistinguishable. Its own calibration ladder resolves 0.5 ms of synchronous work and nothing at all up to 4 ms of work deferred to a microtask — which is exactly where form-contract puts its validation pass — and it separately measures that 0% of those passes ran inside the event being timed. Both sentences are generated from the data, and they sit directly under the row they contradict.

What the lane does resolve at that size: TanStack Form 4.1x and Formik 3.9x the reference per keystroke, with react-hook-form indistinguishable from it.

Two limits, stated rather than papered over

  • The concrete path grammar has no escape, so a field whose key contains a dot cannot be addressed.
  • Validation is proportional to the schema on every settled change. The diff keeps notification proportional to what actually moved, but the pass itself judges the whole root — which is what lets a cross-field rule report against a field that did not move.

Where it stands

The runtime is complete against its design and is exercised by 76 tests, a compile-time test that pins the path union, and a screen that uses all of it. It has not been published to npm, and it has not been run in production by anyone.
